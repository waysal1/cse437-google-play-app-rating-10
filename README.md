# Predicting Google Play Store App Ratings Using Machine Learning

CSE437 Data Science — Group 15

## Problem Statement

Mobile application ratings are an important indicator of user satisfaction and app quality. However, ratings may be influenced by several characteristics such as app category, number of reviews, number of installs, size, price, and app type. This project analyzes the factors associated with Google Play Store app ratings and develops machine-learning regression models to predict an application's rating from its available characteristics.

## Dataset

**Google Play Store Apps** (Kaggle): https://www.kaggle.com/datasets/lava18/google-play-store-apps
License: Creative Commons Attribution 3.0 Unported (CC BY 3.0). See `data/README.md` for the full provenance, expected filenames, and download instructions.

## Target Variable

`Rating` — a continuous value on a 1.0–5.0 scale, representing an app's average user rating.

## Three Approved Research Questions

1. Which app characteristics, such as category, reviews, installs, size, price, and app type, are most strongly associated with Google Play Store ratings?
2. How accurately can machine-learning regression models predict an application's rating using its available characteristics?
3. Which machine-learning model and feature set provides the best rating prediction performance after preprocessing, feature selection, dimensionality reduction, and hyperparameter tuning?

## Notebook Execution Order

Run the notebooks **in this exact order, top to bottom, on a fresh kernel**. Each notebook reads files produced by the previous one.

1. `01_data_audit_and_eda.ipynb` — audits `data/raw/googleplaystore.csv` (shape, missing values, duplicates, the malformed row, outliers); produces no permanent changes to the data.
2. `02_preprocessing.ipynb` — cleans and parses the raw data; saves `data/processed/googleplaystore_clean.csv`.
3. `03_feature_engineering.ipynb` — builds derived features, investigates categorical predictors, performs the train/test split, and evaluates PCA/feature selection (train-only); saves `data/processed/googleplaystore_features.csv` and `data/processed/train_test_split.csv`.
4. `04_modeling_and_tuning.ipynb` — builds the baseline, tunes Ridge and Random Forest via cross-validation, and evaluates the test set once; saves fitted models to `models/`.
5. `05_evaluation_and_error_analysis.ipynb` — loads the saved models, produces diagnostic visualizations, runs the error analysis, and answers the three research questions.

## Reproducing the Results

Running the five notebooks in order on a fresh kernel will regenerate every table and figure referenced in `report/report.md` / `report/report.pdf`, using a fixed random seed (`random_state=42`) throughout for reproducibility. No step in this pipeline fits a scaler, imputer, feature selector, or PCA on anything other than the training split — see each notebook's own leakage-prevention notes for details.
