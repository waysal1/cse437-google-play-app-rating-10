Google Play Store Apps

## Source

Kaggle: https://www.kaggle.com/datasets/lava18/google-play-store-apps

Uploaded to Kaggle by user `lava18`. The data was collected by scraping app listing pages from the Google Play Store; the exact scrape date is not published by the source, but the `Last Updated` field in the main file ranges up to August 8, 2018, indicating the scrape was performed shortly after that date.

The Kaggle dataset page itself renders its licence field via JavaScript and could not be independently verified in text form at the time of writing, so the bundled `license.txt` is cited as the authoritative source rather than a separately asserted claim. Attribution is given to the dataset author (`lava18`) in `report/report.md` under References.

## How to Obtain the Data

If `data/raw/googleplaystore.csv` is missing (e.g. after a fresh clone, if raw data was excluded):

1. Go to https://www.kaggle.com/datasets/lava18/google-play-store-apps
2. Sign in to Kaggle and click **Download** (requires a free Kaggle account), or use the Kaggle CLI:
   ```bash
   kaggle datasets download -d lava18/google-play-store-apps -p data/raw --unzip
   ```
3. Confirm the extracted files are named exactly `googleplaystore.csv` and `googleplaystore_user_reviews.csv` and placed directly under `data/raw/` (not in a subfolder).

## `raw/` vs. `processed/`

- **`raw/`** contains the dataset exactly as downloaded from Kaggle. **Files in `raw/` must remain untouched** — no cleaning, renaming, or edits of any kind. Every notebook treats this folder as read-only input. If a correction is ever needed, it happens in code in `notebooks/02_preprocessing.ipynb`, never by hand-editing the raw file.
- **`processed/`** contains every derived artifact generated by running the notebooks: the cleaned dataset (`googleplaystore_clean.csv`), the engineered feature table (`googleplaystore_features.csv`), the train/test split record, and the various result tables (feature selection scores, PCA variance, tuning results, error analysis, etc.) referenced in the report. Everything in `processed/` is regenerated by re-running `notebooks/01`–`05` in order and should not be edited by hand.

## Known Data Issues (see `notebooks/01_data_audit_and_eda.ipynb` for full evidence)

- One malformed row (`googleplaystore.csv`, original index 10472) has all fields shifted one column to the left due to a missing `Category` value at source; corrected/handled in `notebooks/02_preprocessing.ipynb`.
- 1,181 duplicate rows exist across 9,660 unique `App` names (rows differ mainly in `Reviews` count, consistent with re-scraping over time).
- `Rating` is missing for ~13.6% of rows.
- `Reviews`, `Size`, `Installs`, and `Price` are stored as text and require explicit parsing before use as numeric features.
